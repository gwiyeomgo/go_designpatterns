템플릿 메서드는 기본 클래스에서 알고리즘의 골격을 정의하고 하위 클래스가 전체 알고리즘의 구조를 변경하지 않고 단계를 재정의하도록 허용하는 동작 디자인 패턴입니다

상위클레스 내용을 하위 클레스에서 재정의 하고 싶다

일회용 암호(OTP) 기능의 예를 살펴보겠습니다. OTP를 사용자에게 전달하는 방법에는 여러 가지가 있습니다(SMS, 이메일 등). 그러나 SMS 또는 이메일 OTP 여부에 관계없이 전체 OTP 프로세스는 동일합니다.

1.임의의 n자리 숫자를 생성합니다.
2.나중에 확인할 수 있도록 이 번호를 캐시에 저장합니다.
3.내용을 준비합니다.
4.알림을 보냅니다.
앞으로 도입될 새로운 OTP 유형은 여전히 ​​위의 단계를 거칠 가능성이 높습니다.

따라서 특정 작업의 단계는 동일하지만 이러한 단계의 구현은 다를 수 있는 시나리오가 있습니다. 이는 Template Method 패턴 사용을 고려하기에 적절한 상황입니다.

먼저 고정된 수의 메서드로 구성된 기본 템플릿 알고리즘을 정의합니다. 이것이 우리의 템플릿 방법이 될 것입니다. 그런 다음 각 단계 메서드를 구현하지만 템플릿 메서드는 변경하지 않고 그대로 둡니다


장점
템플릿 코드를 재사용하고 중복 코드를 줄일 수 있다
템플릿 코드를 변경하지 않고 상속을 받아서 구체적인 알고리즘만 변경할 수 있다


단점
리스코프 치환 원칙을 위반할 수 있다
알고리즘 구조가 복잡할 수록 템플릿을 유지하기 어려워진다

리스코프 치환 원칙 =
부모에 있는데
하위 클레스에서 없다면 위반

부모도형에 회전기능이 있는데
하위도형이 회전기능을 없앤다 = 위반
