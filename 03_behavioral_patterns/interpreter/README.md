
인터프리터 패턴
인터프리터는 사람이 작성한 코드를 기계가 이해하도록 바꿈
컴퓨터 외적으로는 통역하는 사람,연주자 등 사전적으로 의미함

자주 등장하는 문제를 간다한 언어로 정의하고 재사용하는 패턴

반복되는 문제 패턴ㅇ르 언어 또는 문법으로 정의하고 확장할 수 있다



ex) 정규식 = 인터프리터 역할

장단점

요청을 캡슐화 하여 호출자와 수신자를 분리하는 패턴

장점
자주 등장하는 문제 패턴을 언어와 문법으로 정의할 수 있다
기존 코드를 변경하지 않고 새로운 expression 을 추가할 수 있다

단점
복잡한 문법을 표현하려면 expression 과 parser 가 복잡해진다.

이렇게 복잡한 코드를 써서 복잡하게 만들만한가?
